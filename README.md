# pi-continuous

用 C++ 不停算 π，每批输出一次，可以一直算下去。

## 算法

两条**互不相干**的数学路线互相验证：

| | 算法 |
|---|---|
| 主计算 | Chudnovsky 级数 + 二分分裂 |
| 交叉验证 | Machin 公式 `π = 16·atan(1/5) − 4·atan(1/239)` |

每批算完，把前 2000 位跟 Machin 的结果逐位比对，对不上就立刻报错退出，
而不是把错的数字当结果输出。

> 写这个程序的时候，Chudnovsky 那一侧真的错过一次，就是这个自检抓出来的。

## 编译

需要支持 C++17 的 g++，以及 boost 头文件库。

```bash
g++ -O2 -std=c++17 -static -o main.exe main.cpp
```

## 用法

```
main.exe [--step N] [--stop M] [--quiet]

  --step N   每批新增 N 位（默认 10000）
  --stop M   算到 M 位后退出（默认一直算）
  --quiet    只输出数字，方便重定向
```

例：`main.exe --stop 100000 --quiet > pi.txt`

运行中在终端按一下回车就停。

## 实测速度

| 算到 | 耗时 |
|---|---|
| 2,000 位 | 0.001 秒 |
| 10,000 位 | 0.022 秒 |

## 踩过的坑

1. **`boost::multiprecision::sqrt` 会静默截断**
   对超大整数开方时它走浮点子程序，位宽不够也不报错，只给到大约三分之一的位数，
   结果整体失真。改成整数牛顿法 `isqrt()`。

2. **PowerShell 直接调 g++ 会静默失败**
   退出码 1、零输出。换 MSYS2 的 bash 就正常。

3. **字符串比较不能直接用 `==`**
   长度不同的两个字符串用 `==` 必然返回 false，会把正确结果误判成错误。
   先截到相同长度再逐位比。

4. **`(6k-5)(2k-1)(6k-1)` 一度被我误判为错**
   实际是对的。先验证再下结论，别靠直觉改代码。
